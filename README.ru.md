# pique

> [English](README.md)

Коллекция конфигураций пользовательского уровня (профилей) [Pi Coding Agent](https://github.com/earendil-works/pi) и инструмент управления запуском `Pi` с выбранной конфигурацией.

## Что делает

pique может хранить неограниченное количество профилей [Pi Coding Agent](https://github.com/earendil-works/pi) и запускать Pi с выбранным профилем. Каждый профиль — полная конфигурация пользовательского уровня.

## Зачем

- Переносить конфигурации Pi между разными машинами.
- Обеспечить стабильность среды исполнения агента.
- Исследовать различные конфигурации и сравнивать между собой для выявления оптимальных решений.
- Развивать конфигурации агентов без риска что-то сломать в текущих процессах.
- Использовать наиболее подходящую конфигурацию для каждой из поставленных задач.

## Отличия от других инструментов

Механизм переключения профилей — уже решённая задача, и несколько расширений Pi делают это хорошо. Можно хранить каталог `~/.pi/agent` под управлением Git, и это может решить проблему версионирования и хранения разных профилей под управлением расширений. Ценность pique в другом:

- Решает только одну задачу: pique не пытается добавлять память агента или что-то еще, только выбор профиля.
- Позволяет запускать Pi с разными профилями параллельно.
- Не зависит от установленных расширений, сохраняя минималистичную конфигурацию.
- Сохраняет воспроизводимость окружения за счет фиксации версий mise.lock.

См. [Альтернативы](docs/ru/alternatives.md) для детального сравнения существующих инструментов.

## Требования

- Linux или macOS
- mise
- git

## Установка

Запустите установщик:

```bash
./install.sh
```

Или клонируйте вручную:

```bash
git clone <repository-url> "$HOME/.config/pique"
cd "$HOME/.config/pique"
mise trust
mise install
ln -sf "$HOME/.config/pique/bin/pique" "$HOME/.local/bin/pique"
```

### Установка в произвольный каталог

Если вы хотите хранить репозиторий не в `~/.config/pique`, а, например, в
`~/projects/pi-configs` или в каталоге dotfiles, это работает:

```bash
git clone <repository-url> "$HOME/projects/pi-configs"
ln -sf "$HOME/projects/pi-configs/bin/pique" "$HOME/.local/bin/pique"
```

Скрипт `pique` разрешает симлинки и находит репозиторий автоматически.
Каталог `$HOME/.config/pique` при этом не нужен.

Альтернативно можно сделать симлинк на весь репозиторий:

```bash
ln -s "$PWD" "$HOME/.config/pique"
```

Тогда `pique` и mise-задачи (`cd "$HOME/.config/pique" && mise run list`) будут
работать как при стандартной установке.

Для переопределения пути вручную используйте переменную окружения:

```bash
export PIQUE_ROOT="$HOME/projects/pi-configs"
```

## Использование

### Список профилей

```bash
pique --list
```

### Запуск Pi с профилем

```bash
cd ~/my-project
pique development
```

Команда:

1. Устанавливает `PI_CODING_AGENT_DIR` на директорию профиля.
2. Запускает Pi в текущей директории.
3. Загружает проектные настройки `.pi/`, если они есть.

### Передача аргументов в Pi

```bash
pique development --version
pique research --print "Проанализируй код"
```

Все аргументы после имени профиля передаются в Pi напрямую.

### Сравнение профилей

```bash
pique --diff minimal development
```

Или из корня репозитория:

```bash
mise run diff -- minimal development
```

Вывод показывает файлы, существующие только в одном профиле, и различия в содержимом общих файлов.

## Профили

| Имя | Назначение |
|-----|-----------|
| `minimal` | Базовая настройка. Без расширений. Низкий уровень размышлений. |
| `development` | Активная разработка. Средний уровень. Файловые инструменты. |
| `research` | Анализ и исследования. Высокий уровень. Расширенный вывод. |

## Как работает

Переменная окружения `PI_CODING_AGENT_DIR` указывает Pi, где искать пользовательскую конфигурацию. По умолчанию Pi использует `~/.pi/agent`. pique устанавливает эту переменную на директорию профиля перед запуском Pi.

Pi читает конфигурацию с двух уровней:

1. **Директория профиля** — настройки, skills, extensions из выбранного профиля.
2. **Директория проекта** — `.pi/` в текущей рабочей директории.

Проектные настройки переопределяют настройки профиля. Ресурсы с обоих уровней объединяются.

### Интеграция с проектом

Для автоматического использования профиля в проекте добавьте в `mise.toml` проекта:

```toml
[env]
PI_CODING_AGENT_DIR = "~/.config/pique/profiles/development"
```

Затем запускайте `pi` из директории проекта с активированным mise.

### Проектные переопределения

Pi читает `.pi/settings.json` из директории проекта. Эти настройки переопределяют настройки профиля:

```json
{
  "defaultModel": "claude-opus-4-1",
  "defaultThinkingLevel": "high"
}
```

Это меняет модель только для этого проекта. Профиль остаётся без изменений.

## Задачи управления

Запуск из корня репозитория:

```bash
mise run list                    # Список профилей
mise run validate                # Валидация всех профилей
mise run diff -- minimal development  # Сравнение профилей
mise run new -- my-profile development  # Создание нового профиля
mise run sync-shared             # Копирование общих skills в профили
```

## Структура репозитория

```
~/.config/pique/
├── mise.toml              # Версии инструментов и задачи управления
├── mise.lock              # Заблокированные версии (коммитить)
├── bin/
│   └── pique              # Команда запуска
├── profiles/
│   ├── minimal/           # Базовая конфигурация
│   ├── development/       # Конфигурация для разработки
│   └── research/          # Исследовательская конфигурация
├── shared/                # Skills, используемые в профилях
├── docs/
│   ├── en/                # Документация на английском
│   ├── ru/                # Документация на русском
│   └── decisions/         # Architecture Decision Records
└── install.sh             # Установщик
```

## Комбинирование с другими инструментами

pique сфокусирован на коллекции конфигураций. Для других задач комбинируйте с существующими инструментами:

| Задача | Инструмент | Как использовать |
|--------|------------|-------------------|
| Переключение в сессии | [pi-profile-switch](https://github.com/VincentFF/pi-profile-switch) | Запуск через pique, `/profile use` внутри сессии |
| Изоляция auth | [pi-profiles](https://github.com/krzyzanowskim/pi-profiles) | Для разделения личное/работа |
| TUI маршрутизации моделей | [pi-profiles-manager](https://github.com/javinnav/pi-profiles-manager) | Установить параллельно |
| Persistent memory | [pi-profile](https://github.com/sovorn-c/pi-profile) | Для workflows с накоплением памяти |

См. [Альтернативы](docs/ru/alternatives.md) для деталей.
