# pique

Библиотека проверенных профилей агента Pi с отслеживанием эволюции через Git.

## Что делает

pique хранит несколько профилей Pi. Каждый профиль — полная конфигурация агент-уровня. Используйте профиль для запуска Pi с проверенными настройками в любой директории проекта.

## Зачем

- Запускать новые проекты с проверенными конфигурациями.
- Сравнивать профили для понимания лучших подходов.
- Собирать лучшие практики AI-ассистированной разработки.
- Развивать настройки агента со временем.
- Документировать решения через Architecture Decision Records.
- Сохранять базу знаний, независимую от конкретной машины.

## Отличия от других инструментов

Механизм переключения профилей — уже решённая задача, несколько инструментов делают это хорошо. Ценность pique в другом:

| Аспект | pique | Другие инструменты |
|--------|-------|---------------------|
| **Источник истины** | Git-репозиторий | Локальные файлы |
| **История** | Полная Git-история, ветки, blame | Отсутствует или export/import |
| **Сравнение** | `git diff`, `pique --diff` | Не встроено |
| **Документирование решений** | ADR с обоснованием | Недоступно |
| **Сохранение знаний** | Почему приняты решения | Только что сделано |
| **Воспроизводимость** | mise.lock фиксирует точные версии | Различается |

См. [Альтернативы](docs/ru/alternatives.md) для детального сравнения существующих инструментов.

## Требования

- Linux или macOS
- mise
- git

## Установка

Запустите установщик:

```bash
./install.sh
```

Или клонируйте вручную:

```bash
git clone <repository-url> ~/.config/pique
cd ~/.config/pique
mise trust
mise install
ln -sf ~/.config/pique/bin/pique ~/.local/bin/pique
```

## Использование

### Список профилей

```bash
pique --list
```

### Запуск Pi с профилем

```bash
cd ~/my-project
pique development
```

Команда:

1. Устанавливает `PI_CODING_AGENT_DIR` на директорию профиля.
2. Запускает Pi в текущей директории.
3. Загружает проектные настройки `.pi/`, если они есть.

### Передача аргументов в Pi

```bash
pique development --version
pique research --print "Проанализируй код"
```

Все аргументы после имени профиля передаются в Pi напрямую.

### Сравнение профилей

```bash
pique --diff minimal development
```

Или из корня репозитория:

```bash
mise run diff -- minimal development
```

Вывод показывает файлы, существующие только в одном профиле, и различия в содержимом общих файлов.

## Профили

| Имя | Назначение |
|-----|-----------|
| `minimal` | Базовая настройка. Без расширений. Низкий уровень размышлений. |
| `development` | Активная разработка. Средний уровень. Файловые инструменты. |
| `research` | Анализ и исследования. Высокий уровень. Расширенный вывод. |

## Как работает

Переменная окружения `PI_CODING_AGENT_DIR` указывает Pi, где искать пользовательскую конфигурацию. По умолчанию Pi использует `~/.pi/agent`. pique устанавливает эту переменную на директорию профиля перед запуском Pi.

Pi читает конфигурацию с двух уровней:

1. **Директория профиля** — настройки, skills, extensions из выбранного профиля.
2. **Директория проекта** — `.pi/` в текущей рабочей директории.

Проектные настройки переопределяют настройки профиля. Ресурсы с обоих уровней объединяются.

### Интеграция с проектом

Для автоматического использования профиля в проекте добавьте в `mise.toml` проекта:

```toml
[env]
PI_CODING_AGENT_DIR = "~/.config/pique/profiles/development"
```

Затем запускайте `pi` из директории проекта с активированным mise.

### Проектные переопределения

Pi читает `.pi/settings.json` из директории проекта. Эти настройки переопределяют настройки профиля:

```json
{
  "defaultModel": "claude-opus-4-1",
  "defaultThinkingLevel": "high"
}
```

Это меняет модель только для этого проекта. Профиль остаётся без изменений.

## Задачи управления

Запуск из корня репозитория:

```bash
mise run list                    # Список профилей
mise run validate                # Валидация всех профилей
mise run diff -- minimal development  # Сравнение профилей
mise run new -- my-profile development  # Создание нового профиля
mise run sync-shared             # Копирование общих skills в профили
```

## Architecture Decision Records

Значимые решения документируются в `docs/decisions/` в формате MADR 4.0.0. Каждый ADR фиксирует:

- Контекст и проблему
- Рассмотренные варианты
- Почему выбранный вариант победил
- Последствия (положительные и отрицательные)
- Как проверить, что решение всё ещё актуально

Текущие решения:

| ADR | Решение |
|-----|---------|
| [0001](docs/decisions/0001-use-isolation-via-pi-coding-agent-dir.md) | Использовать `PI_CODING_AGENT_DIR` для изоляции профилей |
| [0002](docs/decisions/0002-use-git-first-approach.md) | Подход Git-first для управления конфигурациями |
| [0003](docs/decisions/0003-use-thin-launcher-not-extension.md) | Тонкий лаунчер вместо in-process расширения |
| [0004](docs/decisions/0004-use-madr-for-decision-records.md) | MADR 4.0.0 для записи решений |
| [0005](docs/decisions/0005-use-mise-for-runtime-management.md) | mise для управления рантаймом |
| [0006](docs/decisions/0006-store-profiles-in-config-directory.md) | Хранение профилей в `~/.config/pique/` |

См. [Руководство по ADR](docs/ru/adr-guide.md) для написания новых.

## Сравнение профилей

Директория `comparison/` содержит тест-кейсы для оценки профилей:

| Кейс | Что проверяет |
|------|---------------|
| `code-quality` | Корректность, полноту, стиль ответов |
| `speed` | Скорость ответа и эффективность вызовов инструментов |
| `token-usage` | Расход токенов на эквивалентные задачи |

Запуск сравнения:

```bash
./comparison/scripts/run-comparison.sh minimal development
```

Результаты сохраняются в `comparison/results/` и коммитятся для дальнейшего использования.

См. [Руководство по сравнению](docs/ru/comparison.md) для деталей.

## Структура репозитория

```
~/.config/pique/
├── mise.toml              # Версии инструментов и задачи управления
├── mise.lock              # Заблокированные версии (коммитить)
├── bin/
│   └── pique              # Команда запуска
├── profiles/
│   ├── minimal/           # Базовая конфигурация
│   ├── development/       # Конфигурация для разработки
│   └── research/          # Исследовательская конфигурация
├── shared/                # Skills, используемые в профилях
├── docs/
│   ├── en/                # Документация на английском
│   ├── ru/                # Документация на русском
│   └── decisions/         # Architecture Decision Records
├── comparison/            # Сравнительные тест-кейсы
│   ├── cases/             # Тестовые промпты и критерии
│   ├── scripts/           # Скрипты автоматизации
│   └── results/           # Результаты сравнения
└── install.sh             # Установщик
```
