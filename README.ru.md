# pique

Коллекция курируемых профилей для агента Pi.

## Что делает

pique хранит несколько профилей Pi. Каждый профиль — полная конфигурация агент-уровня. Используйте профиль для запуска Pi с проверенными настройками в любой директории проекта.

## Зачем

- Запускать новые проекты с проверенными конфигурациями.
- Сравнивать профили для понимания лучших подходов.
- Собирать лучшие практики AI-ассистированной разработки.
- Развивать настройки агента со временем.

## Требования

- Linux или macOS
- mise
- git

## Установка

```bash
git clone <repository-url> ~/.config/pique
cd ~/.config/pique
mise trust
mise install
ln -sf ~/.config/pique/bin/pique ~/.local/bin/pique
```

Или запустите установщик:

```bash
./install.sh
```

## Использование

### Список профилей

```bash
pique --list
```

### Запуск Pi с профилем

```bash
cd ~/my-project
pique development
```

Команда:

1. Устанавливает `PI_CODING_AGENT_DIR` на директорию профиля.
2. Запускает Pi в текущей директории.
3. Загружает проектные настройки `.pi/`, если они есть.

### Передача аргументов в Pi

```bash
pique development --version
pique research --print "Проанализируй код"
```

### Сравнение профилей

```bash
pique --diff minimal development
```

## Профили

| Имя | Назначение |
|-----|-----------|
| `minimal` | Базовая настройка. Без расширений. Низкий уровень размышлений. |
| `development` | Активная разработка. Средний уровень. Файловые инструменты. |
| `research` | Анализ. Высокий уровень. Расширенный вывод. |

## Как работает

Переменная окружения `PI_CODING_AGENT_DIR` указывает Pi, где искать пользовательскую конфигурацию. По умолчанию Pi использует `~/.pi/agent`. pique устанавливает эту переменную на директорию профиля перед запуском Pi.

Pi читает конфигурацию с двух уровней:

1. **Директория профиля** — настройки, skills, extensions из выбранного профиля.
2. **Директория проекта** — `.pi/` в текущей рабочей директории.

Проектные настройки переопределяют профильные. Ресурсы с обоих уровней объединяются.

### Интеграция с проектом

Для автоматического использования профиля в проекте добавьте в `mise.toml` проекта:

```toml
[env]
PI_CODING_AGENT_DIR = "~/.config/pique/profiles/development"
```

Затем запускайте `pi` из директории проекта с активированным mise.

## Задачи управления

Запуск из корня репозитория:

```bash
mise run list                    # Список профилей
mise run validate                # Валидация всех профилей
mise run diff -- minimal development  # Сравнение профилей
mise run new -- my-profile development    # Создание нового профиля
mise run sync-shared             # Копирование общих skills в профили
```

## Структура репозитория

```
~/.config/pique/
├── mise.toml          # Инструменты и задачи
├── bin/
│   └── pique          # Команда запуска
├── profiles/
│   ├── minimal/
│   ├── development/
│   └── research/
├── shared/            # Skills, используемые в профилях
├── sessions/          # Сессии Pi (gitignored)
└── docs/
    ├── en/
    └── ru/
```
