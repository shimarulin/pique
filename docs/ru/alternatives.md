# Альтернативные инструменты

## Обзор

pique — не единственный способ управления профилями Pi. Существует несколько инструментов, и даже обычный Git-репозиторий поверх `~/.pi/agent` решает часть задачи. Этот документ описывает альтернативы и помогает выбрать.

## Сравнение

| Инструмент | Механизм | Хранение | Для чего лучше |
|------------|----------|----------|----------------|
| **pique** (этот проект) | Тонкий лаунчер + `PI_CODING_AGENT_DIR` | Git-репозиторий, отдельные профили | Выбор профиля как единственная задача; параллельный запуск; независимость от расширений |
| **Git поверх `~/.pi/agent`** | Версионирование директории агента | Git-репозиторий, одно активное состояние | Простое версионирование; работа с одним профилем |
| **pi-profile** (sovorn-c) | Лаунчер + `PI_CODING_AGENT_DIR` | `~/.pi/profiles/<name>/` | Изолированные профили с persistent memory |
| **pi-profiles** (krzyzanowskim) | Лаунчер + `PI_CODING_AGENT_DIR` | `~/.pi/agent-profiles/<name>/` | Разделение auth (личное/работа) |
| **pi-profiles-manager** (javinnav) | In-process расширение, TUI | `~/.pi/agent/pi-profiles/` | Управление модельными маршрутами в сессии |
| **pi-profile-switch** (VincentFF) | In-process расширение + лаунчер | JSON-дескрипторы | Переключение в сессии с выбором ресурсов |

## Когда использовать pique

Используйте pique, когда хотите:

- Запускать Pi с разными профилями параллельно.
- Переключение профилей, не зависящее от установленных расширений.
- Воспроизводимую среду исполнения за счёт фиксации версий (mise.lock).
- Минималистичный инструмент, решающий ровно одну задачу.

## Когда использовать альтернативы

### Git поверх `~/.pi/agent`

Держите директорию агента Pi под версионным контролем.

Подходит, когда:

- Вы используете одну конфигурацию за раз.
- Вам нужно простое версионирование без дополнительных инструментов.
- Вам не нужно запускать несколько профилей одновременно.
- Вы готовы переключать конфигурации через Git-операции (checkout, ветки).

Ограничения:

- Активен только один профиль одновременно.
- Переключение требует Git-операций, а не одной команды.
- Версии рантайма (Node.js, сам Pi) не зафиксированы.
- Сессии и auth смешиваются между конфигурациями без дополнительного управления.

Настройка:

```bash
cd ~/.pi/agent
git init
git add -A
git commit -m "Initial Pi configuration"
```

Для экспериментов создайте ветку, внесите изменения и смержите обратно.

### pi-profile (sovorn-c)

Используйте, когда нужно:

- Persistent memory на профиль (USER.md, HINDSIGHT.md, FAILURES.md).
- Шаблоны для новых профилей (coding, research, personal).
- Экспорт/импорт как `.tgz`-бандлы.
- Создание профиля из существующего состояния Pi.

Установка: `npm install -g @sovorn/pi-profile`

Ограничения:

- Профили хранятся вне версионного контроля (если не добавить Git самостоятельно).
- Нет параллельного запуска разных профилей из одной установки.
- Версии рантайма не зафиксированы.

### pi-profiles (krzyzanowskim)

Используйте, когда нужно:

- Строгое разделение auth между профилями.
- Автоматическая синхронизация настроек между профилями.
- Общие сессии между профилями.
- Переменные окружения на профиль.

Установка: `mise use -g npm:@krzyzanowskim/pi-profiles@latest`

Ограничения:

- Фокус на разделении auth; остальные аспекты конфигурации вторичны.
- Нет версионного контроля профилей.
- Версии рантайма не зафиксированы.

### pi-profiles-manager (javinnav)

Используйте, когда нужно:

- Интерактивный TUI для управления профилями.
- Маршрутизация моделей (orchestrator + subagents).
- Циклическое переключение профилей горячими клавишами.
- Переключение профилей внутри сессии.

Установка: `pi install npm:pi-profiles-manager`

Ограничения:

- Работает только внутри запущенной сессии Pi.
- Требует установленного и загруженного расширения.
- Нет версионного контроля профилей.
- Не может запустить Pi; управляет конфигурацией только после старта.

### pi-profile-switch (VincentFF)

Используйте, когда нужно:

- Переключение профилей внутри сессии без перезапуска.
- Декларативные JSON-профили со схемой.
- Выбор ресурсов через glob-паттерны.
- Фильтрация MCP-серверов и инструментов на профиль.
- Runtime-оверлеи для временных изменений.

Установка: `npm install -g pi-profile-switch`

Ограничения:

- Более сложная настройка (JSON-дескрипторы профилей).
- Требует понимания модели ресурсов Pi.
- Нет версионного контроля профилей (если не добавить Git самостоятельно).
- Версии рантайма не зафиксированы.

## Комбинирование инструментов

Можно использовать pique вместе с другими инструментами:

### pique + pi-profile-switch

Используйте pique для хранения и запуска профилей. Используйте pi-profile-switch для гибкости внутри сессии.

1. Храните профили в репозитории pique.
2. Используйте `pique <profile>` для запуска Pi.
3. Внутри сессии используйте `/profile use <name>` из pi-profile-switch для временных переключений.

### pique + pi-profile

Используйте pique для версионированных конфигураций. Используйте pi-profile для изолированных рабочих профилей с памятью.

1. Поддерживайте конфигурации в pique.
2. Используйте pi-profile для создания рабочих копий с persistent memory.
3. Импортируйте полезные изменения обратно в pique через Git.

### pique + Git поверх ~/.pi/agent

Используйте Git для прямого управления `~/.pi/agent` вместе с профилями pique.

1. Держите конфигурацию Pi по умолчанию под Git в `~/.pi/agent`.
2. Используйте профили pique для специализированных конфигураций.
3. Переносите полезные изменения между ними.

| Независимость от расширений | pique |
| Воспроизводимый рантайм | pique |
| Простое версионирование без новых инструментов | Git поверх `~/.pi/agent` |

| Изоляция auth | pi-profiles |
| Переключение в сессии | pi-profile-switch |
