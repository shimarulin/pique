# Управление Node.js и pnpm через mise

В проекте используется [mise](https://mise.jdx.dev/) для управления версиями инструментов. Конфигурация хранится в `.mise.toml`. Это позволяет всем участникам команды и CI использовать одинаковые версии Node.js, pnpm и других инструментов.

## Текущая конфигурация

Файл `.mise.toml` в корне проекта:

```toml
[tools]
node = "24.21.0"
pnpm = "12.11.2"
pi = "1.1.0"
```

> **Примечание:** `pi` — это вспомогательный инструмент, не связанный с Node.js. Он управляется независимо.

## 1. Обновление Node.js

### 1.1. Через команду `mise use`

Самый простой способ — указать новую версию прямо в командной строке. `mise` обновит `.mise.toml` и установит нужную версию.

```bash
# Обновить до последней версии в ветке 24
mise use node@24

# Или до точной версии
mise use node@24.21.0
```

После выполнения команды проверьте:

```bash
mise current node
node -v
```

### 1.2. Вручную через `.mise.toml`

Отредактируйте файл `.mise.toml`, заменив строку с `node`:

```toml
[tools]
node = "24.21.0"
```

Затем выполните:

```bash
mise install
```

## 2. Установка pnpm

### 2.1. Через `mise` (рекомендуется)

Сначала узнайте последнюю доступную версию:

```bash
mise latest pnpm
# например: 12.11.2
```

Затем установите её и зафиксируйте в `.mise.toml`:

```bash
mise use pnpm@12.11.2
```

После этого `pnpm` будет доступен в проекте автоматически. Проверить:

```bash
mise current pnpm
pnpm -v
```

Команда `mise use` добавляет в `.mise.toml`:

```toml
[tools]
pnpm = "12.11.2"
```

### 2.2. Поле `packageManager` в `package.json`

Поле `packageManager` — это **метаданные**, а не механизм установки. Оно сообщает инструментам (CI, Renovate, `corepack`, самому `pnpm`), какая версия пакетного менеджера ожидается в проекте.

```json
{
  "packageManager": "pnpm@12.11.2"
}
```

Это поле **безопасно сочетается с `mise`**: `mise` устанавливает и активирует `pnpm`, а `packageManager` документирует ожидаемую версию. Рекомендуется добавлять его в проект.

### 2.3. Почему мы не используем `corepack`

`corepack enable` устанавливает шимы для `pnpm` и `yarn`, которые перехватывают вызовы и подменяют бинарь на нужную версию. Это **конфликтует с `mise`**: обе системы пытаются управлять версией `pnpm`, и итоговое поведение зависит от порядка `PATH`.

**Правило проекта:** версия `pnpm` управляется только через `mise` (`.mise.toml`). `corepack enable` не используем. Поле `packageManager` в `package.json` при этом можно и нужно держать — оно не активирует corepack само по себе.

## 3. Проверка актуальности версий

### 3.1. `mise outdated`

Показывает устаревшие инструменты.

```bash
# Показать устаревшие инструменты в текущем диапазоне
mise outdated

# Показать устаревшие инструменты с учётом последних доступных версий
mise outdated --bump
```

Пример вывода:

```
Plugin  Requested  Current  Latest
node    24.21.0    24.21.0  24.21.1
pnpm    12.11.2    12.11.2  12.12.0
pi      1.1.0      1.1.0    1.2.0
```

### 3.2. `mise ls`

Показывает установленные и активные версии инструментов.

```bash
# Список всех инструментов
mise ls

# Только активные в текущем проекте
mise ls --current

# Показать, какие версии устарели
mise ls --outdated
```

### 3.3. `mise latest`

Узнать последнюю доступную версию конкретного инструмента.

```bash
mise latest pnpm
mise latest node@24
```

## 4. Обновление инструментов

### 4.1. Обновление в рамках текущего диапазона

Если в `.mise.toml` указан диапазон (например, `node = "24"`), команда `mise upgrade` обновит инструмент до последней версии в этом диапазоне.

```bash
mise upgrade node
mise upgrade pnpm
```

### 4.2. Обновление с изменением версии в `.mise.toml`

Флаг `--bump` обновляет инструмент до самой последней версии и переписывает версию в `.mise.toml`.

```bash
# Обновить pnpm до последней версии
mise upgrade pnpm --bump

# Обновить все инструменты
mise upgrade --bump
```

### 4.3. Обновление до конкретной версии

```bash
mise use pnpm@12.12.0
mise use node@24.22.0
```

## 5. Частые вопросы

### 5.1. Нужно ли что-то делать для `pi` после обновления Node.js?

Нет. `pi` — независимый инструмент. Обновление Node.js на него не влияет. Для обновления `pi`:

```bash
mise upgrade pi --bump
```

### 5.2. Какую команду использовать для установки `pnpm`?

```bash
mise latest pnpm           # узнать версию
mise use pnpm@<version>    # установить и зафиксировать
```

Или одной командой:

```bash
mise use pnpm@latest
```

### 5.3. Как обновить `pnpm`?

```bash
mise upgrade pnpm --bump
```

## 6. После обновления Node.js или pnpm

После смены версии Node.js или pnpm рекомендуется переустановить зависимости:

```bash
# Удалить node_modules (если есть проблемы с нативными модулями)
rm -rf node_modules

# Установить зависимости заново
pnpm install
```

Если возникают ошибки с нативными модулями:

```bash
pnpm rebuild
```
