# Архитектура

## Обзор

pique — репозиторий профилей агента Pi. Каждый профиль — директория, которую Pi читает как директорию конфигурации агент-уровня.

## Проектные решения

### Изоляция профилей

Переменная окружения `PI_CODING_AGENT_DIR` указывает Pi, где искать директорию агента. По умолчанию Pi использует `~/.pi/agent`. pique хранит профили в отдельных директориях внутри `profiles/`.

Скрипт запуска устанавливает эту переменную перед стартом Pi. Такой подход:

- Не изменяет `~/.pi/agent`.
- Позволяет существовать нескольким профилям одновременно.
- Даёт возможность переключать профили без резервного копирования.
- Отделяет системную конфигурацию Pi от версионированных профилей.

### Изоляция сессий

Каждый профиль имеет отдельную директорию сессий `sessions/<profile>/`. Скрипт запуска устанавливает `PI_CODING_AGENT_SESSION_DIR` при наличии директории сессий. Это предотвращает появление данных сессий одного профиля в другом.

### Двухуровневая конфигурация

Pi читает конфигурацию с двух уровней:

1. **Директория агента** — управляется `PI_CODING_AGENT_DIR`. Содержит пользовательские настройки, skills, extensions.
2. **Директория проекта** — `.pi/` в рабочей директории. Содержит проектные настройки.

Проектные настройки переопределяют настройки агента. Ресурсы с обоих уровней объединяются. Например:

- Директория агента содержит `skills/mise-integration/`.
- Директория проекта содержит `skills/project-specific/`.
- Pi загружает оба skills.

### Общие ресурсы

Директория `shared/` содержит skills и extensions, используемые в нескольких профилях. Задача `mise run sync-shared` копирует эти ресурсы в каждый профиль, где их нет.

Это позволяет:

- Иметь единый источник для общих skills.
- Профилям переопределять общие ресурсы при необходимости.
- Легко обновлять общие компоненты.

### Управление инструментами

mise управляет версиями Pi и Node.js:

- `mise.toml` объявляет версии.
- `mise.lock` записывает точные разрешённые версии.
- `mise install` устанавливает объявленные версии.

Скрипт запуска использует mise для поиска бинарника Pi. Если mise недоступен, скрипт использует системный PATH.

## Структура файлов

```
profiles/<name>/
├── settings.json      # Настройки агент-уровня
├── AGENTS.md          # Инструкции, загружаемые при старте
├── APPEND_SYSTEM.md   # Дополнение к промпту (опционально)
├── SYSTEM.md          # Замена промпта (опционально)
├── mcp.json           # MCP-серверы (опционально)
├── keybindings.json   # Привязки клавиш (опционально)
├── extensions/        # Расширения (опционально)
├── skills/            # Skills (опционально)
├── prompts/           # Шаблоны промптов (опционально)
└── themes/            # Темы (опционально)
```

## Безопасность

- Репозиторий не содержит API-ключей.
- Pi хранит учётные данные в `auth.json` внутри директории агента.
- Сессии могут содержать чувствительные данные. Директория `sessions/` в .gitignore.
- Не коммитьте файлы `auth.json`.

## Совместимость

- Linux (все дистрибутивы)
- macOS (Intel и Apple Silicon)
- bash (доступен на обеих платформах)
